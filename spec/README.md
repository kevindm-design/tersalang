# Specification

`design-doc.md` and `language-reference.md` are the Tersalang specification for language 0.1-draft: the Design Doc explains the design and its reasons, and the Language Reference explains how to write programs. If the two disagree, the Design Doc wins. Language changes go through a TEP (`teps/`). Points that no spec settles yet are in [`docs/spec-notes.md`](../docs/spec-notes.md).

| File | Contents |
| --- | --- |
| `design-doc.md` | The design: syntax, types, effects, contracts, the RL harness, and the reasons behind each rule |
| `language-reference.md` | The language written out for programmers, with the diagnostic catalog in Appendix B |
| `tersa.ebnf` | The grammar from design §7.2 |
| `tersa.lark` | The conflict-free LALR grammar oracle, and the source of `tersa.gbnf` |
| `tersa.gbnf` | Generated by `tersa grammar --format gbnf`; do not edit by hand (see [`docs/gbnf.md`](../docs/gbnf.md)) |
| `diagnostics.yaml` | The master list of diagnostic codes and messages; Appendix B mirrors it row for row |
| `fuel.yaml`, `limits.yaml` | Fuel costs and default limits the interpreter checks against |
| `schemas/diagnostic.schema.json` | `tersa.diagnostic/0.1` |
| `schemas/result.schema.json` | `tersa.result/0.9`, the harness episode |

The repository uses these names: the manifest `tersa.toml` and lockfile `tersa.lock` (not read yet), the Python package `tersalang` with the command `tersa`, and Tersalang Enhancement Proposals in `teps/`. The language was formerly called AIOWL; the specs say Tersalang.
