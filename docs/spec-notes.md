# Spec notes

These notes record how the interpreter settles points that the specs in `spec/` (Design Doc v0.6.0 and Language Reference Draft v0.6.0) leave open or do not yet describe. Where a note differs from a spec, the note describes the code. `spec/diagnostics.yaml` is the master code list. The interpreter follows the yaml. Appendix B of the reference is the catalog, row for row.

## Names

- Package: `src/tersalang/`. Command: `tersa`, entry `tersalang.cli:main`.
- Source extension: `.tersa`.
- Manifest and lockfile names, when a package tool exists: `tersa.toml` and `tersa.lock`. This version does not read either file. A mismatch would be `E2101`.
- Grammars: `spec/tersa.ebnf` (section 7.2), `spec/tersa.lark` (LALR oracle and the source of `spec/tersa.gbnf`). `tersa grammar --format gbnf` regenerates the GBNF file. CI checks that the committed file matches a fresh generation.
- Schema ids: `tersa.diagnostic/0.1` and `tersa.result/0.9`.
- Enhancement proposals are TEPs and live in `teps/`.

## Lexical and syntax

- Any invalid UTF-8 byte sequence is `E0001`, and so is a leading byte-order mark. The message includes the byte offset. The rest of that line is skipped. The CLI and the conformance runner decode with `surrogateescape` so the lexer sees the bad bytes.
- Span ends are exclusive, in the LSP style.
- `let _` and `var _` are accepted. The EBNF says `LOWER`. The prose in section 7.4 requires a binding, including a discard.
- The lexer emits `NAMED_ARG` for `name =` inside parentheses. That includes `with (` field initializers, because the lexer cannot tell them from calls.
- A file with no final newline still produces a synthetic `NL` when the last line had tokens.
- A blank line, or a line that is only a non-doc comment, breaks doc-comment attachment. One optional space after `##` is stripped.
- `do` is the only token on its line, for `while`, `for`, `using`, `test`, function bodies, and lambdas. A trailing comment is allowed. Anything else on that line is `E1000` ("expected `do` on its own line"), including a body such as `do return`.
- From the `)` that closes a lambda's parameter list until that lambda's `end`, the lexer treats the surrounding bracket depth as zero again, so line breaks produce `NL`. Continuation tokens still join lines. Nested lambdas use a stack. A function type (`returns function (Int) returns Int`, or a type after `:`) does not open a frame. A lambda body is still one expression.
- The Lark file and the hand parser both accept imports and declarations in any order. The copied EBNF still lists imports before declarations. Two separate newline repetitions in Lark are a reduce/reduce conflict, so the grammar uses one item list. Duplicate top-level names are `E2021`. Constant cycles are `E2003`.
- Extra diagnostic codes are listed in `spec/diagnostics.yaml` and `EXTRA_CODES`. Generic syntax that the grammar does not allow is `E1000`.

## Types and runtime

- `try` belongs to the innermost function or lambda. A lambda whose whole body is `try` usually fails to type-check, because the success type must also match the declared return type.
- Negative indexes are out of range. `slice` requires `0 <= start <= end <= count` and otherwise traps `T6010`. It does not clamp.
- `0^0` is `1`. A negative `math.pow` exponent fails `requires` with `T6101`.
- A failed contract quotes its condition as written: `T6101` "precondition failed: `<condition>`", `T6102` "postcondition failed: `<condition>`", `T6103` "invariant failed: `<condition>`". The span is the condition. `related` is "called from here" at the call for `T6101` and `T6102`, and `` `R` built or updated here`` at the construction or `with` for `T6103`. `values` holds each name, field path (`r.width`), `result`, and `old(...)` in the condition, in order of first appearance, read without spending fuel; functions, modules, types, and cases are left out. This is the JSON shape of Language Reference §17.2. The human layout is Design §18.1 (`trap[T6101]: ...`, then `-->`, the related note, `blame`, and one `name = value` line each).
- `math.min`, `math.max`, `math.abs`, and `math.clamp` are one generic function restricted to `Int`, `Int64`, and `Float`. There is no `Numeric` interface and no overloading.
- `Float.sqrt` and `math.sqrt` share behavior. A negative input is a canonical NaN.
- `list.sort` with one argument orders `Int`, `Int64`, and `Text`. Other element types need the comparator.
- Replacing a map entry keeps its position. Removing it and inserting it again moves it to the end. Mutable `insert` of an existing key moves it to the end.
- An `Int` literal is `E3023` only when the expected type of that literal expression is `Int64`. `let n: Int64 = 1 + 0` is `E3000`.
- In `==` and `!=`, an operand that needs a type from context (`None`, a payload-free case of a generic choice such as `Empty`, or `[]`) takes it from the other operand, as design §8.2's bidirectional checking implies: `xs.get(0) != None` and `None == xs.get(0)` check, in a contract or anywhere else. With no context (`let x = None`, `None == None`) it is `E3010` at the name as written, not at the module start.
- `main` must return `Unit` or `Result[Unit, E]` to run (`E3034`). A missing `main` is a run error, not a check error.
- Tests have no `uses` clause. The checker allows effects inside tests. The runner checks grants when a test actually calls them.
- `W3050` is reported for `List.at` unless the call is in the `then` body of an `if` whose condition proves both `index >= 0` (also `index > 0` or `0 <= index`) and `index < receiver.length()`, and both the receiver and the index are names. `receiver.length() > index` counts as the upper bound. A `< length` test alone does not suppress the warning, because a negative index is still out of range. Literal indexes still warn. `else` does not inherit the proof. The check does not look through arbitrary boolean expressions.
- A case name that collides with another case, including a prelude case, is `E2022` at the later declaration and again at each unqualified use. Qualifying it (`Choice.Case`) avoids the clash. Unqualified `Invalid` remains `Utf8Error.Invalid` until a second `Invalid` is declared.
- An ignored `Result` is `E3002`. An ignored `Option`, or any other non-`Unit` value, is `W3001`.
- `E2030` is reported when `set` names something that is not a `var`.
- A name after `exposing`, or after a module qualifier, that the module does not export is `E2005`. An unknown `std.*` module is `E4013`. An unknown record field is `E3082`. An unknown field or method on a non-record type is `E3004`. An unknown value name is `E2000`. An unknown type is `E3008`.
- `File`, `FileError`, and `Utf8Error` are prelude names. Importing one again is `E2021`. `Json` and `JsonError` are prelude names too. `PythonError` is a prelude record with fields `type_name: Text` and `message: Text`, which is the official v0.5.3 shape. A foreign function can return `Result[T, PythonError]`.
- A second `implements` block for the same interface and type is `E3043`. `show` requires `T: Showable` at check time (`E3045`, "Type is not Showable"). Showable is derived for every type except function types, resource types, and mutable collections, and for any record, choice, list, map, set, option, or result that contains one. A type variable is Showable, Equatable, or Hashable only when its constraints say so (`[T: Showable]`; `Hashable` also gives `==`). `<error>` does not produce a second diagnostic.
- Constraints are checked at each call site. A type argument that misses one is `E3046` "Type does not implement the interface", except that a missed `Showable` is `E3045` and a missed `Hashable` is `E3042`. Built-in `Comparable` covers `Int`, `Int64`, `Text`, `Bool`, and `Ordering`; any other type needs `implements Comparable[T]`. A constraint that names no interface is `E3008`.
- Constraints on a record's or choice's type parameters (`record Keyed[K: Hashable, V]`, `choice Ranked[T: Comparable]`) are checked the same way, with the same codes. A written type such as `Keyed[Float, Int]` checks its concrete arguments; a type variable written there is not checked, the same as a `Set` element, because a signature is resolved before its own constraints are in scope. A construction (`Keyed(key = k, value = 1)`, `Best(x)`) checks every inferred argument, including a type variable, against the enclosing function's constraints. Field types inside the declaration see the declaration's constraints. The `implements` fix hint is given only for user records and choices.
- An interface function is called by its name (`describe(r)`, `compare(a, b)`) or with method syntax (`r.describe()`). A top-level function or local with the same name wins, which is how a harness task's free function replaces its interface header. With a concrete type the checker picks the `implements` block for the type of the first parameter typed with the interface's type parameter; no block is `E3046`. With a constrained type variable the call dispatches on that argument's runtime type, which matches the static choice because types are erased (§8.5). If no parameter has the interface's type (for example `function default() returns T`), a call from generic code is `E3010` ("cannot pick an implementation of `default` for type parameter T ...", with a fix); a call with a concrete expected type still resolves. It is not resolved at run time: reference §5.11 has no explicit type arguments at a call, and design §8.5 lets the interpreter erase types, so generic code has no type to dispatch on. An interface function used as a value needs a function type from its context (`List.map(xs, describe)`), otherwise `E3010`. An interface with no type parameter, such as a task's `interface Solution`, cannot be implemented: Appendix A's `implements_decl` requires `type_args`, and design §8.6 and reference §5.12 write `implements Interface[Type]`, so the grammar and GBNF are unchanged. Such an interface is met by top-level functions with its names, which is what harness tasks use. `implements Solution` stays `E1000`, `implements Solution[Int]` is `E3007` ("takes no type parameter", with a fix naming the functions to define), and a type-argument count that differs from the interface's is `E3007` too. Calling one of its functions without a top-level function of that name is `E3046`.
- An `implements` block must supply every function the interface lists (`E3044`), each with the interface's type with `T` replaced (`E3000` otherwise), and may not add others (`E3004`). It inherits the interface's `requires` and `ensures`, which see the arguments under the interface's parameter names even if the implementation renames them, and are reported once even when several blocks inherit them. Naming an unknown interface is `E3008`. Method syntax on a choice or built-in type also reaches top-level functions whose first parameter has that type.
- In host mode, `foreign "python:module.name"` calls that Python attribute. A Python exception is `T6401` unless the return type is `Result[T, PythonError]`, in which case the call returns `Error(PythonError(type_name, message))`. A Python `int` that does not fit in `Int64` is `T6402`. A parameter or return type with no Python mapping is `E4020` at check time. `Result` is accepted only as that special return type.
- Importing the current module is `E2002`, and the message lists the cycle. A cycle that runs through another file cannot be formed: those imports are still `E2000`, because this interpreter loads one file plus `std`.
- User modules other than the one file being checked are `E2000`. Only `std.*` imports resolve.
- `Net` has no implementation.
- JSON values are the choice `Null`, `Bool(value)`, `Number(literal)`, `String(value)`, `Array(items)`, `Object(entries)`. `Number` keeps the decimal text. `Object` entries are a `Map` in insertion order. `Json.Bool` stays qualified because `Bool` is a type. Unqualified `Null` is the JSON null, also written `Json.Null`. There is no `JsonNull`: `tersa check` and `tersa run` both report the name as `E2000`, and the pattern `case JsonNull` against a `Json` as `E3000`. The specs say only that `std.json` parses into a `Json` choice, so these case names are the interpreter's.
- `FileError` is `NotFound(path)`, `Denied(path)`, or `Io(message)`. Each one names only the path text the program passed, never the resolved host path or the granted root. A missing file or folder is `NotFound`, an OS permission error is `Denied`, and anything else is `Io` with a message such as ``"`d`: Is a directory"`` (the OS reason after the program's path). `Utf8Error` is `Invalid(index)`. `JsonError` is `Invalid(index, message)`.
- `Bytes.from_hex` and `Bytes.from_list` return `None` for invalid input. They do not trap. `Bytes.of_hex` and `Bytes.of_list` return `Bytes` and trap `T6013` on the same bad input (`odd number of hex digits`, or `byte value N is outside 0..255`). `show` of a `Bytes` value is `Bytes.of_hex("…")`. `from_hex` still uses `bytes.fromhex` after an even-length check, so whitespace is accepted when the raw text length is even. `of_hex` uses that same check.
- A closed file is `T6012`. Checked programs cannot reach one: `using` closes the file after the body, and storing, returning, or capturing a resource is `E3072`. The trap is covered by a unit test, not a `.tersa` program.
- `Text.split` with an empty separator is `T6101`.
- `Random.int(low, high)` is inclusive of `low` and exclusive of `high`. An empty range is `T6101`.
- Grapheme segmentation is an approximation: a combining mark stays with the previous character. Full UAX #29 tables are not shipped.
- Unicode case mapping uses the host `unicodedata` version. `tersa version` reports it.
- The virtual clock is used in every mode. `now` is `0`. `monotonic` starts at `0` and increases by `1` on each call. The wall clock is not read.
- `Env` does not read the process environment. It reads only the host allowlist. This CLI does not pass process variables through.
- `FileRead`, `FileWrite`, and `Net` are scoped effects and need an explicit scope: `--allow FileRead=FOLDER`, `--allow FileWrite=FOLDER`, `--allow Net=HOST`. A scoped effect with no scope or an empty one, an unscoped effect given a scope (`--allow Console=x`), and an unknown or mis-cased effect name (`--allow Bogus`, `--allow console`) are each `I9010`, exit 4, before anything runs. The Python API (`run_text`, `run_tests`) applies the same rule to its `grants` dictionary. A path outside a granted root is `T6301`.
- `tersa test` ends stdout with a summary line, `4 tests passed, 1 doc example passed` (Language Reference §19), after the tests' own output. Failed counts are added only when nonzero (`3 tests passed, 1 test failed, 0 doc examples passed, 1 doc example failed`), and singular nouns are used for 1. A trap that stops the whole run, such as a failing constant, counts the test or example that was running as failed. `--json` leaves the line out so stdout still ends with the diagnostic array.
- Property tests default to seed `0` and share one fuel budget across the cases of one test (`--fuel` is per test). `tersa test` gives each test its own fuel, memory-unit, and output budget. Running out of fuel, memory units, or call depth traps `T6201`, `T6202`, or `T6203` and fails only that test. Every failing test is reported, in source order. Generators try `0`, `1`, `-1`, the `Int64` bounds, and small random values, then shrink toward `0`.
- `--fuel` must be at least `1`. Fuel `0` is `I9010`. `--max-depth` must be at least `1`. `--output-bytes` may be `0`. Output past that cap is `W6205`, a reported result. The run is kept. `I9012` is reserved and is not emitted.
- Decimal digits in literals are ASCII `0`–`9`, matching the grammar. A Unicode digit such as `²` is not part of a number. `str.isdigit` is not used for that scan, because it accepts characters `int(text, 10)` rejects.
- `--json` (on `check`, `run`, `test`, and `sandbox`) writes to stdout. stdout ends with exactly one line that holds the `tersa.diagnostic/0.1` JSON array, `[]` when there is nothing to report. For `run`, `test`, and `sandbox`, the program's own console output comes first, so a tool reads the last line. Human-readable diagnostics are not printed in that mode; stderr carries only the program's `print_error` output and the `error: ...` line of a `main` that returns `Error`. An invalid limit flag is also reported in the array (`I9010`, exit 4).
- Lark is a development dependency. The runtime dependency set is empty.
- `sys.setrecursionlimit` is only a host backstop. Call depth is counted by the interpreter.
- `Float.fma` uses `math.fma` when the Python version has it, and libm otherwise.
- A value that is not Showable still has a defined rendering, used by diagnostic `values`, a `fail` message that is not `Text`, test propagation, and a `main` that returns `Error`. It is a placeholder for the whole value, not a trap and not a mixed canonical form: `<function>` for a function, `<resource>` for a resource, `<mutable>` for a mutable collection, and `<value>` for anything else that is not Showable (including a record, choice, list, map, set, option, or result that contains one). `show` itself returns that same text.
- `tersa sandbox` runs one program with only the grants and limits the host passes. Defaults are fuel 100,000, memory units 100,000, output 1,048,576 bytes, and a 5,000 ms wall clock. Each flag overrides its own default. `tersa run` stays unlimited until a flag is set. There is no ambient file, console, clock, random, or env access. If `main` declares an effect that was not granted, the run is refused before it starts (`E4010`, a check failure, exit 3). A call that reaches an ungranted effect at run time, including inside a test, traps `T6302`. `FileRead`, `FileWrite`, `Net`, and `Python` cannot be granted in RL mode: a task that lists one fails to load, and `tersa sandbox`, `run --mode rl`, and `test --mode rl` refuse an `--allow` for one with `I9017` (exit 4) before anything runs. `Env` is granted only when `task.toml` sets fixed values.
- The integer cap defaults to 65,536 bits (`T6204`). Every `T6204`, whether from an operation, a conversion, a literal, or a parse, has `values` `{"max_int_bits": "N"}`: the run's cap, under the name the task file, `spec/limits.yaml`, and design §12.6 use. Fuel, memory units, and call depth are deterministic traps (`T6201`, `T6202`, `T6203`). Output past the cap is `W6205`; the run and the RL episode continue. A candidate wall-clock limit is `T6208` (reward 0, `C` 0, `E` 0, exit 2). The in-process message is `in-process wall-clock backstop reached (N ms)`. The harness child timeout (30 s unless a test passes another budget) is `child process wall-clock backstop reached (N s)`. Both are `T6208` for a candidate, because the host cannot be told apart from a slow program. `tersa sandbox` and `tersa run` stay `I9013` (reward null, exit 4). A reference stopped during validation or measurement keeps `I9013` on that reference episode. `tersa harness validate` fails its gate and exits 1. `tersa harness run` falls back with `E_basis_reason` `"reference_did_not_execute"`.
- The harness is described in full in `docs/harness.md`. The points the specs leave open: `validate` collects mutation sites from function and test bodies, groups them by edit kind, spreads them with a step from the SHA-256 of the source, draws them round-robin, and keeps at most 16 well-typed texts; a splice that does not parse or type-check is skipped and not counted. Return replacements follow the declared type (`0`/`1`, `true`/`false`, `0.0`/`1.0`, `""`/`"mut"`); `Unit` and other types get none, and contracts are not edited. Interface contracts replace the contracts of the functions the interface names, including a replacement with an empty list; a helper the interface does not name keeps its own. A parse failure and zero hidden tests use `C` 0, and a check failure uses `check_credit`, except `E3047`, which uses 0. A zero-fuel reference still scores `E` 1, through the `max(ref_fuel, 1)` floor. There is no clip on the reward.
- The episode JSON follows `tersa.result/0.9`. `toolchain.python` and `toolchain.platform` differ by machine; determinism compares `canonical_bytes`, which replaces those two fields. `interface.tersa` must parse (`I9021`), and its module name cannot be the keyword `interface` (the example uses `task_spec`). A child process that exits without JSON, or whose JSON fails `result.schema.json` or does not match the attempt, task, and backend it was sent, scores 0 with `C` 0 rather than being discarded, so a crash cannot be farmed as a null reward. `TERSALANG_HARNESS_CRASH=1`, `TERSALANG_HARNESS_FORGE=1`, and `TERSALANG_HARNESS_SIGNAL` are test hooks in the worker, not language features.
- The combined module keeps every candidate declaration except `test` blocks and `main`, including its own interfaces and `implements` blocks. Hidden interfaces, their functions, and hidden `implements` blocks are renamed under `@hidden`. A hidden `implements` of a public interface (`Comparable` or one in `interface.tersa`) is kept only for a hidden type; for a type the candidate can name it is dropped, because it would change the candidate's own dispatch or raise `E3043` from hidden code. A hidden call `x.helper()` is renamed with the helper; a builtin method of the same public name still takes precedence.
- Task-load codes, all infrastructure and all exit 4: `I9014` missing `task.toml`, `I9015` language mismatch, `I9016` unknown effect, `I9017` effect RL mode cannot grant (also when written with a scope, as in `FileRead=data`), `I9018` a reward weight that is a number outside 0..1, `I9019` seed policy, `I9020` missing or empty `hidden/`, `I9021` a task source did not parse, `I9022` a `task.toml` field has the wrong type, `I9025` the reference solution does not match `interface.tersa`. An attempt that does not match it is `E3047`: stage check, `C` 0, reward 0, full detail in the agent view. A limit field that is present but not an integer, and a reward weight that is not a number, are `I9022`. `I9010` is a limit that is missing, not positive, or out of range, or an `effects` entry with a scope on an effect that takes none (`Console=out`). The checks run in that order over the whole list: unknown names, then refused effects, then stray scopes. `I9012` and `T6021` stay reserved.
- Exit codes for `tersa run` and `tersa sandbox` follow Design Doc §17.3: 0 success, 1 `main` returns Error, 2 trap, 3 check failure, 4 infrastructure or toolchain error. `tersa harness run` uses 4 for every `infrastructure_error` whose code starts with `I`, 2 for a candidate resource trap (`T6206`, `T6207`, `T6208`), and 0 for every other scored episode, including reward 0. `1` is also used where 2, 3, and 4 do not fit: `tersa test` when a test fails or traps (conformance `test-fail` expects 1), `tersa fmt --check` when a file would change, and `tersa harness validate` when the task fails its gate.
- OS caps are `setrlimit` on Linux and macOS, plus bubblewrap on Linux when it is installed. The harness child inherits only an allowlist of environment variables on every OS, and bubblewrap binds only the Python install, the `tersalang` package, the shared libraries, the task directory, and the attempt (docs/harness.md, Isolation). nsjail and gVisor are not launched (`I9024`, reward null, exit 4). Windows job objects are unsupported. A candidate killed by the memory cap or the CPU cap scores 0 (`T6206`, `T6207`) under every backend, including `none`.
- `tersa fmt` and `tersalang.fmt.format_source` apply design §18.2. There is no layout configuration. `--check` and stdin are host interfaces.
- `# fmt: skip`, as a whole stripped line, still leaves that file's bytes unchanged, but only after the file parses. `tersa fmt`, `tersa fmt --check`, and `scripts/check_fmt.py` parse a marked file and, if parsing fails, print the diagnostic and exit 3. Only the rewrite is skipped. The CRLF fixture, the newline-suppression fixture, and the `W1103` mixed `and`/`or` fixture use the exact marker, they parse, and they stay byte-stable. Formatting the mixed form would add parentheses and drop the warning. Formatting the newline fixture would collapse the continuations that fixture exists to keep. Those three stay exempt from `tersa fmt --check` diffs and from the decoding profile.
- A full-line comment that is not the exact marker, but matches `#` plus optional whitespace plus `fmt` plus optional whitespace plus `:` plus optional whitespace plus `skip` in any case, warns `W1104`, whose message is: Format-skip comment is not exactly `# fmt: skip`. `tersa fmt` (including `--check` and stdin) and `tersa check` (including `--parse-only`) emit it, with or without other errors. `tersa run`, `tersa sandbox`, and `tersa test` collect it with the checker's warnings and print them only alongside a check error or a trap that stops the run (design §18.2.1); a run that succeeds, or whose `main` returns `Error`, prints none. The harness never reports it. The warning does not change a successful exit code. The file is formatted. Extra words and a trailing comment after code do not warn. `W1104` is the next syntax warning after `W1103`.
- `tersa fmt` on a file or a directory exits 3 when a file does not parse, prints that file's diagnostic, and does not write it. That includes a `# fmt: skip` file. `tersa fmt --check` exits 1 only when a parseable file would change. A directory that has both a parse error and a file that would change exits 3. `tersa fmt conformance` exits 3 because that tree contains fixtures that are supposed to fail lexing or parsing. CI runs `scripts/check_fmt.py`, which passes every file the formatter can read to `tersa fmt --check`, and exits 3 when a marked file does not parse. Unmarked fixtures that are supposed to fail lexing or parsing stay out of that check.
- Parentheses are AST nodes (`GroupExpr`). `tersa fmt` never removes a parenthesis the author wrote, so `(a + b) * c`, `(1 + 2)`, and `((x))` all stay as written. The only parentheses it adds are one group around an `and` that is the direct operand of an `or`, which is what clears `W1103`. That group is a new `GroupExpr`, so the first format of such a file does change the AST in exactly that way and no other: the inserted group has the same meaning as the bare `and`. Besides layout (whitespace, line breaks, and where comments sit) the formatter also sorts imports and `exposing` lists. Every other AST node is unchanged. `tests/unit/test_wording_issues.py` parses, formats, and reparses every example and corpus file (with `# fmt: skip` lines removed) and compares the ASTs field by field, allowing only those two differences. The second format is stable: `fmt(fmt(x)) == fmt(x)`.
- Function types are printed `function(Int) returns Int`. Lambdas keep a space: `function (x: Int)`.
- A line that cannot break inside `()[]{}` may exceed 100 columns. `uses`, an import path, and a `for all` parameter list stay on one line, because a newline would end the production.
- `do` is printed on its own line. A lambda's `do` and `end` are indented two spaces past the line where that `function` starts.
- `W1104` is the diagnostic for a near-miss format-skip comment. A parse failure reuses the parse diagnostic. `--check` uses exit status 1. A warning alone stays exit 0.
- GBNF is standard llama.cpp: no `( !rule )` lookahead. Both profiles reserve keywords: `lower` is a trie of rules that excludes the 57 words in Lark's `LOWER` lookahead. Every statement and declaration ends in `nl`, and gaps follow the lexer: a word after a word needs a space, and a line break may only go inside brackets or after a continuation token. Where a rule can end in a name or a bracket the grammar asks for the space, so `(a)and b` and `7mod 2` don't match though the parser accepts them. The full profile still accepts a file whose last line has no line break. The parser's `E1000` for a keyword used as a name is unchanged. Floats include `1e10`. Text includes the lexer's backslash escapes. Both profiles encode `E0010` and `E0012` and cap comments (at most 100 full-line comments before the first token, 30 per line break after code, 500 characters per comment); the cap is the one way a `tersa fmt` result can be rejected, since the formatter keeps comments as written. The `decoding` profile tightens whitespace and keeps the formatter's blank-line rule (none at the start, at most one in a row): see `docs/gbnf.md` for exactly what it rejects and what it still accepts. `# fmt: skip` files are not required to match it.

## Code list

`spec/diagnostics.yaml` is the master list. A code that is not `reserved: true` has a conformance expect or an entry in `tests/unit/test_diagnostics_coverage.py` `GAPS`. `tests/unit/test_diagnostics_coverage.py` fails when source emits a code that is missing or reserved, and when a live code has neither a test nor a skip.

`docs/diagnostics.md` is generated from the yaml by `scripts/gen_diagnostics_doc.py`, one `### CODE` heading per code, and the same test fails when it is stale. Every diagnostic's `docs_url` is `https://github.com/kevindm-design/tersalang/blob/main/docs/diagnostics.md#` plus the lowercased code (`#e3045`), because GitHub anchors headings by their lowercased text and has no anchors inside a YAML file. The page holds the catalog message, severity, category, and note, then a wrong example and a fixed example. The wrong example is a conformance program that expects the code (106 codes): a program with a `# fixed:` header is preferred, then the file named after the code, then the shortest. A program that contains a byte-order mark, a tab, a carriage return, or bytes that are not UTF-8, or is over 2,000 bytes, is linked, not shown. The fixed example is that program after its `# fixed: OLD => NEW` header edits, applied in order to the first occurrence, with `\n` for a line break and `\\` for a backslash (94 codes). `tests/test_conformance.py` runs each fixed program the way its `# expect:` line runs the wrong one and requires exit 0, no error, and no diagnostic with that code. A program with no fixed form says why in `# no-fix:` (12 codes, such as a fix that is a grant or a larger budget), and a test requires one or the other. The 18 live codes that no program produces (host, task-load, and OS codes, plus `E2101` and `T6012`) say so on the page; the 3 reserved codes have no example.

`E1000` is the syntax code. One of its messages is "expected `do` on its own line". `E3033` is a returned value of the wrong type. A bare `return` in a non-`Unit` function is `E3032`. `E3006` is a case with fields used as a bare name. `E3003` is an argument list of the wrong length. `E0025` is only a bad hex or binary literal. `E3045` is a call to `show` whose type is not Showable. `T6021` is reserved, because `show` is checked statically (`E3045`). `I9012` is reserved. Truncation is `W6205`. `I9013` is the wall-clock infrastructure code. A candidate's own clock is `T6208`. An OS memory kill is `T6206`. An OS CPU kill is `T6207`. `I9023` is reserved.

## Known limitations

- `E2101` has a catalog entry and a skipped test. Nothing reads `tersa.lock`.
- `I9011` matches the catalog and the reference, and nothing emits it, because no Unicode version is pinned.
- Cross-file import cycles are not loaded. A self-import of the current module is `E2002`. Any other user module is `E2000`.
- Lark is a parse oracle, not a second lexer. The diff test rebuilds source from hand tokens. `NAMED_ARG` has priority 1 so `name =` is not split into an identifier and `=`.
- The language server, `Net`, and multi-file package loader are not in this version. The language sandbox, bubblewrap on Linux, and the reward harness are in. nsjail and gVisor are not launched.
- The decoding GBNF profile constrains whitespace lexemes only: it rejects tabs, CR, two or more spaces between tokens, a trailing comment not preceded by exactly two spaces, trailing whitespace, a missing final newline, a blank line at the start of the file, and two blank lines in a row. It does not enforce operator, comma, or bracket spacing, indentation depth, which allowed line break is used, whether one blank line or none separates declarations, import order, or `W1103` parentheses. `tersa fmt --check` remains the layout gate. `# fmt: skip` is kept for the three fixtures that parse and must not be rewritten.
- `I9010` is `validate_limits`, an illegal task limit, or an invalid host grant, not a `.tersa` file. `I9013` is a wall-clock infrastructure stop, also not a `.tersa` file. `T6206`, `T6207`, and `T6208` are candidate resource traps, also not produced by a `.tersa` program. `I9014` through `I9022` are task-load failures. `I9024` is a backend that cannot launch. `T6302` is the runtime ungranted-effect trap; `E4010` stays the pre-run check on `main`.
